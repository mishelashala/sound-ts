superset-ts

Dialect + CLI: brand type → plain types + Account.is / Account.from. Stock tsc / Vite consume output only — not a Microsoft/TypeScript fork.

Authoring (phase 1)

Prefer .sts files. Stock TypeScript language service will red-squiggle brand type inside ordinary .ts / .tsx. The VS Code TextMate grammar covers .sts; injection into .ts only helps highlighting, not the checker.

String literal unions only:

// file: roles.sts
brand type Account = "admin" | "regular";

function greet(role: Account): string {
  return role === "admin" ? "hello, admin" : "hello";
}

// After CLI transform, Account is also a runtime companion:
greet(Account.from("admin"));
Account.is("guest");   // false
Account.from("guest"); // throws

CLI quickstart

git clone https://github.com/mishelashala/superset-ts.git
cd superset-ts
pnpm install && pnpm build && pnpm test

# one file
node packages/cli/dist/cli.js ./example.sts -o ./out/example.ts

# directory → out/
node packages/cli/dist/cli.js ./src -o ./out

Binaries: sts / superset-ts. Point bundlers at the output directory.

Caveats (v0)

  • Parser / comments: parse.ts matches brand type with a regex. Comment-skipping is incomplete — a decl inside a line or block comment can still match and be rewritten. Avoid live-looking decls in comments until a proper skip lands.
  • Editor: author in .sts to avoid stock tsc red squiggles on the dialect keywords.

VS Code (thin, local-only)

packages/vscode registers .sts, highlights brand type (including in .ts), and can shell out to the CLI. No full custom checker in v0.

Not on the Marketplace yet — install from this repo (VSIX / “Install Extension from Location…” / Extension Development Host). Marketplace publish comes later. Also not on npm.

defineLiteralSet?

Internal emit / runtime helper — not the public API. Authors write brand type; the CLI expands. Do not treat import { defineLiteralSet } as the product.

Non-goals (v0)

  • No Microsoft / TypeScript fork to maintain
  • No custom checker or LSP fantasy in v0
  • Phase 1: string literal unions only
  • Closed literal union + runtime — not nominal brands
  • Not a full schema validation library
  • Not on npm yet
  • VS Code extension not on Marketplace yet (local install only)
  • defineLiteralSet is not the authoring surface
